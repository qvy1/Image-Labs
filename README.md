## Lab 2 — Digital Image Fundamentals

**Outcome #1:** Explain how digital images are represented and manipulated in a computer.

### Parts covered

| Part | Description |
|------|-------------|
| Part 0 | Environment check and preparing the images |
| Part 1 | Image sampling and quantization |
| Part 2 | Arithmetic operations on images |
| Part 3 | Sets and logical operations |

### Session tasks

| Task | Description |
|------|-------------|
| Task 1 | Change the sampling and quantization parameters and observe the effects |
| Task 2 | Subtraction, adding a constant of 175, set difference, symmetric difference, intersection |

### Points addressed in the notebook

- **`uint8` overflow.** Adding or subtracting two images with plain NumPy arithmetic wraps
  around instead of clipping, so a bright pixel plus a bright pixel can become dark. The
  notebook quantifies how many pixels are affected and compares the wrapped result with the
  saturated one (`np.clip` / `cv2.add` / `cv2.absdiff`).
- **Quantization step size.** `256 // levels` truncates, so the formula is exact only when the
  number of levels divides 256. With 9 levels it can produce 10 distinct values.
- **Set operations on grayscale.** The bitwise operators apply to the bit patterns of the
  intensities and are meaningful only on binary images. The grayscale generalisation uses
  `np.maximum` for union and `np.minimum` for intersection, and reduces to the binary
  definitions when the only values present are 0 and 255.
- Six set identities, including De Morgan's laws, are verified pixel by pixel.

### Images used

`A.png` and `B.png` are generated by the notebook as two overlapping binary shapes (a disk and
a square), which makes the result of each set operation easy to read by eye. The grayscale
images are the same `skimage.data` samples used in Lab 1.

## Lab 3 — Image Manipulations using OpenCV

**Outcome #1:** Explain how digital images are represented and manipulated in a computer, and
apply geometric transformations to images.

| Part | Description |
|------|-------------|
| Part 1 | Reading, displaying and saving an image |
| Part 2 | Converting between colour spaces (BGR, YUV, HSV, LAB) |
| Task 1 | Geometric transformations — scaling, rotation by 120°, shear |
| Task 2 | Intensity transformations — negative, log, power law |

### Points addressed in the notebook

- **Rotation crops the image.** Rotating with the default canvas size cuts off the corners; the
  output size has to be computed from the bounding box of the rotated rectangle.
- **Interpolation is lossy.** Rotating by 120° three times restores the orientation but not the
  pixel values. Measured inside the inscribed circle, where nothing is lost to the canvas, the
  mean absolute error is 3.0 — interpolation error alone.
- **JPEG is lossy, PNG is not.** Saving and re-reading a `.jpg` does not return the same array.
- **Choosing gamma by measurement.** Rather than guessing, standard deviation was computed
  across a range of gamma values and the maximum selected.
- Two errors in the manual's code were corrected: `cv2.imshow` with `cv2.waitKey` blocks the
  Jupyter kernel, and `print [x for x in dir(cv2)...]` is Python 2 syntax.

## Lab 4 — Intensity Transformations and Filtering

**Outcome #2:** Write a program that implements fundamental image processing algorithms.

| Part | Description |
|------|-------------|
| Part 1 | Thresholding — fixed, other types, Otsu, adaptive |
| Part 2 | Histogram processing — contrast stretching |
| Task 1 | Rescale intensities to the 3rd–80th percentiles |
| Task 2 | Histogram equalisation with `exposure.equalize_hist` |
| Task 3 | Histogram matching — rocket as reference, Chelsea as input |

### Points addressed in the notebook

- **`equalize_hist` returns a float image in 0–1**, not `uint8` in 0–255. Plotting its histogram
  with `range=(0, 255)` puts 99.6% of the pixels in the first bin and produces an empty chart.
- **`match_histograms` uses `channel_axis`**; the `multichannel` argument found in older
  tutorials has been removed from current scikit-image.
- **A threshold of 0 is not a no-op.** `THRESH_BINARY` compares strictly greater, so only the
  pure-black pixels stay black — verified against the count of zero-valued pixels.
- Otsu's method and adaptive thresholding were added to address the difficulty of choosing a
  threshold, which the manual raises but does not implement.
- Equalisation and matching are approximate because images are discrete; verified on the
  cumulative histograms.

## Lab 5 — Spatial Filtering: Smoothing and Sharpening

**Outcome #2:** Write a program that implements fundamental image processing algorithms.

| Part | Description |
|------|-------------|
| Part 1 | What spatial filtering is — the convolution kernel |
| Part 2 | Unsharp masking |
| Task 1 | Convolution with a 7x7 box filter |
| Task 2 | Gaussian filtering at 5x5 and 21x21 |
| Task 3 | Sharpening with a 3x3 Laplacian |

### Points addressed in the notebook

- **The sign of the Laplacian formula.** OpenCV's kernel has a negative centre, so
  `f - laplacian` sharpens. Using `f + laplacian` raises no error but **inverts** the detail:
  measured at the strongest peaks and troughs, bright points go to 0.0 and dark points to 1.0.
- **Standard deviation cannot verify sharpening.** It rises for both signs, so only the
  direction of the change at peaks and troughs distinguishes the correct formula.
- **A 5x5 "Gaussian" is not Gaussian.** For small windows OpenCV substitutes the binomial kernel
  1, 4, 6, 4, 1 over 16 rather than sampling the curve, so passing the derived sigma explicitly
  gives a result 4 levels away rather than identical.
- **`sigma = 0` means "derive from the kernel size"**, giving sigma 1.10 and 3.50 for the two
  filters used.
- The 7x7 box kernel built by hand matches `cv2.blur` exactly, and the mean brightness is
  preserved because the weights sum to 1.
- The Laplacian amplifies noise by about eight times; blurring first (Laplacian of Gaussian)
  keeps it near the input level.

## Lab 6 — Filtering in the Frequency Domain

**Outcome #1:** Write a program that implements fundamental image processing algorithms.

| Part | Description |
|------|-------------|
| Part 1 | What the frequency domain is — the 2-D FFT and its spectrum |
| Part 2 | The Laplacian filter in the frequency domain |
| Part 3 | The convolution theorem |
| Task 1 | Apply the Sobel filters in the frequency domain |

### Points addressed in the notebook

- **`fftfreq` is not centred**, despite the comment in the manual — and that is correct. Its
  output order (`0, +, +, -, -`) matches the layout of `fft2`, so the element-by-element
  multiplication lines up. `fftshift` is for display only and must never be applied to an array
  about to be used in a calculation.
- **`ifftshift` before `fft2`** in `center_embed_kernel` moves the kernel's centre to index
  `[0,0]`, where the transform expects the origin. Omitting it translates the output by half the
  image in each direction — verified by comparing against the correct result rolled by
  `(M//2, N//2)`, which matched exactly. The result still looks like a plausible edge map, which
  is what makes this error dangerous.
- **The frequency product is convolution, not correlation.** Lab 5 noted that `cv2.filter2D`
  performs correlation; for the symmetric kernels there it made no difference, but the Sobel
  kernels are antisymmetric. Measured: `1.5e-15` against the spatial convolution and `6.6`
  against the correlation of the same image.
- The FFT treats the image as periodic, so frequency-domain filtering wraps at the edges. The
  spatial comparisons therefore use `mode='wrap'`; the disagreement with other border modes is
  confined to the border pixels.
- Low and high frequencies were separated with a circular mask and reconstructed independently,
  giving a blurred image and an edge-only image from the same spectrum. 98.97% of the energy sits
  in 4.30% of the coefficients.
- `.real` after the inverse FFT is justified rather than assumed: the largest imaginary component
  is `7.7e-16`, floating-point rounding rather than signal.
